# 輪を組む｜モザイクモール港北 クリスマス参加型企画（静的サイト版）

サーバー・データベースを使わず、**GitHub Pagesにそのまま置けば動く**構成です（クレメラリーと同じ形）。

## ファイル構成

```
ring-tree-static/
├── ring.html       # 来場者向けメイン画面（QRの読み取り先）
├── qr-print.html   # 印刷用QRコード一覧（社内用・来場者には案内しない）
└── README.md
```

ビルド不要・依存パッケージ不要。この2つのHTMLファイルをそのままリポジトリに置くだけです。

## 仕組み

- 館内10箇所に、それぞれ `ring.html?spot=r-b1` のように**スポットIDだけが違う同一URL**のQRコードを掲示します
- QRを読み取ると `ring.html` が開き、URLの `spot` パラメータを見て「この輪を灯す」処理をその場で行います
- 進捗（どの輪をすでに灯したか）は、来場者のスマートフォンの **localStorage**（そのブラウザだけに残るデータ）に保存されます
  - サーバーがないため、来場者ごとの識別や「同じQRを他人と使い回していないか」の検証はできません。前回ご案内した「スタッフが完成画面を目視確認するだけでOK」という運用方針とはもともと相性の良い方式です
- 10個すべて灯すと、その場で引換コード（例: `MMK-AB3C-9XYZ`）を画面内に生成して表示します。このコードはサーバーで発行・検証しているものではなく、画面ごとに一意な見た目を出すための演出です

## 公開手順（GitHub Pages）

1. GitHubで新しいリポジトリを作成する（例: `ring-tree-static`）
2. `ring.html` と `qr-print.html` をpushする

   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<あなたのアカウント>/ring-tree-static.git
   git push -u origin main
   ```

3. GitHubのリポジトリ画面で **Settings → Pages** を開く
4. **Source** を `Deploy from a branch` にし、Branch を `main` / `/ (root)` にして **Save**
5. 数分後、`https://<あなたのアカウント>.github.io/ring-tree-static/ring.html` が公開されます（クレメラリーの「GitHub Pages」欄と同じ仕組みです）

## QRコードの作成

1. 公開されたURL（`.../ring.html`）を確認する
2. `qr-print.html` をブラウザで開く（ローカルでファイルをダブルクリックするだけでOK。これは印刷用の社内ツールなので公開リポジトリに置いたままで問題ありません）
3. 上部の入力欄に、手順1で確認したURLを入力する
4. 10箇所ぶんのQRコードが自動で表示されるので、「印刷する」ボタンで印刷、またはスクリーンショットして館内掲示物に組み込む
   - `qr-print.html` は各QR画像を [goqr.me の無料QR生成API](https://goqr.me/api/) から都度読み込んで表示しています。オフラインでは動かないのでご注意ください
   - 設置場所名（ラベル）を変更したい場合は、`qr-print.html` 内の `SPOTS` 配列を書き換えてください（`id` は `ring.html` 側と対応しているので変更しないでください）

## 会期中の運用・サポート

- 来場者から「進捗が消えた／リセットしたい」と言われた場合：`ring.html` の一番下にある「この端末の進捗をリセットする」を、その来場者自身の端末で押してもらってください（確認ダイアログが出ます）。サーバー側の管理機能はないため、これが唯一のリセット手段です
- ブラウザのプライベートモード（シークレットモード）で開くと、閉じた時点でlocalStorageが消えるため進捗が保存されません。案内文などで通常モードでの利用を推奨してください

## 既知の制約（サーバー版との違い）

| | サーバー版（Node+DB） | 静的版（本ファイル） |
|---|---|---|
| ホスティング | Render等（有料プラン推奨） | GitHub Pages（無料） |
| 進捗の保存場所 | サーバーのデータベース | 来場者のスマホのブラウザ内 |
| 同じQRの使い回し防止 | できる（来場者ごとに1回だけカウント） | できない（端末を変えれば何度でも進む） |
| 端末の機種変更・ブラウザ変更時 | 影響なし（Cookie/DBで管理） | 進捗がリセットされる（localStorageは端末ごと） |
| 運用の手間・コスト | サーバー管理が必要 | ほぼゼロ（pushするだけ） |

今回は「スタッフが画面を目視確認するだけでOK」という運用方針に合わせているため、この制約は許容範囲として静的版を採用しています。もし将来的に「1人1回」を厳密に守りたくなった場合は、前回お渡ししたサーバー版（Node+SQLite、`ring-tree-app.zip`）に切り替えることでカバーできます。
